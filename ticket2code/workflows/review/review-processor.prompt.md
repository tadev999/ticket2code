# Review Processor — Output Templates

This is the entrypoint for review report schema and templates used by /t2c_review.

## Required Load Order (mandatory)
Read files in this order before composing review report sections:
1. ticket2code/review/processor-specs/01-language-and-convention.md
2. ticket2code/review/processor-specs/02-section-1-commit-metadata.md
3. ticket2code/review/processor-specs/03-section-2-ac-evaluation.md
4. ticket2code/review/processor-specs/04-section-3-code-quality.md
5. ticket2code/review/processor-specs/05-section-4-conclusion.md

## Non-negotiable report requirements
- Use one review report file per ticket at docs/report/<TICKET-ID>_reviews_<YYYYMMDDHHmm>.md.
- Always include Section 1 (commit metadata and diff summary).
- After evaluation, append Section 2 (AC mapping), Section 3 (code quality), and Section 4 (conclusion).
- Review report is separate from implementation report generated by /t2c_code.

## Workflow invariants
- Section 1 must include both before/base commit metadata and after/HEAD commit metadata (hash, author, date), plus diff statistics.
- Section 1 must include the exact comparison range used for review: `<before_commit>..HEAD`.
- Section 2 must map each decomposed AC to specific code locations in diff and/or existing codebase.
- Section 3 must check against repository-specific engineering standards (coding style, logging, test coverage).
- Section 4 must conclude with compliance status: Pass / Conditional Pass / Fail.

## Delegation map
- Section 1 template: processor-specs/02-section-1-commit-metadata.md
- Section 2 template: processor-specs/03-section-2-ac-evaluation.md
- Section 3 template: processor-specs/04-section-3-code-quality.md
- Section 4 template: processor-specs/05-section-4-conclusion.md
